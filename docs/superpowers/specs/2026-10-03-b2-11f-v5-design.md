# B2-11F v5 Interior Design Master — Design Specification

Date: 2026-10-03  
Repository: `Legosea/b2-11f-3d-viewer`  
Target: GitHub Pages  
Workflow basis: `akseolabs-seo/interior-design-master`

## 1. Goal

Rebuild B2-11F as a browser-based editable residential 3D project using the Interior Design Master case contract and runtime-starter. The result must prioritize source-faithful architecture first, then apply the user's selected warm modern dollhouse / ArchViz visual language.

The current v4 one-file viewer is not a geometry source of truth and will not be reused as the architectural model.

## 2. Source hierarchy

Use these sources in this order:

1. **B2-11F PDF plan** (`2024-07-14-Model(1).pdf`) as the architectural topology and source-coordinate reference.
2. **User-supplied measurements**:
   - floor-to-floor height: 3300 mm
   - living-room W3 width: 2680 mm
   - W3 height: 1900 mm
   - W3 sill: 500 mm above finished floor
3. **User-supplied style reference image** as design-language evidence only; it does not establish dimensions or architecture.
4. Existing v1–v4 viewer code may be consulted only for interaction ideas, never for wall coordinates.

The PDF title block states scale **1/60** and identifies the sheet as **B2-11F**. All extracted geometry must remain traceable to source coordinates.

## 3. Confirmed architectural topology

The white model must reproduce the plan shown in the source PDF:

- entry from the upper side into the central circulation / open area;
- upper-left bathroom with shower / WC / basin zone;
- left bedroom with its plan-shown door and lower exterior opening;
- large central open living/dining/kitchen area;
- upper-right bedroom with its plan-shown door and fixed cabinetry zone;
- lower-right bathroom;
- lower-right balcony;
- lower-center exterior opening / W3 assembly;
- columns / shafts / fixed wet-area boundaries visible in the plan.

No extra bedrooms, corridors, studies, closets, or partition walls may be invented.

## 4. Geometry pipeline

### 4.1 Intake
Preserve the source PDF under the case `inputs/plan/` and record SHA-256, MIME type, sheet role, and page count.

### 4.2 Source-coordinate extraction
Extract vector paths / linework from the PDF where possible. Keep a transform from PDF source coordinates to metres. Do not infer architecture from the previous viewer.

### 4.3 Scale
Use the PDF's 1/60 scale only after verifying it against at least one user-confirmed dimension, preferably W3 = 2680 mm. If the measured PDF W3 opening does not match, record the discrepancy and use the user-confirmed W3 dimension as the local calibration anchor.

### 4.4 plan.json
Create stable IDs for:
- rooms;
- exterior and interior walls;
- columns / shafts;
- doors and swing directions;
- windows / sliding doors;
- wet areas;
- balcony;
- fixed cabinetry / utilities;
- circulation routes;
- source assumptions.

Each wall and opening must store evidence status: `confirmed`, `estimated`, `inferred`, or `unknown`.

### 4.5 W3
W3 must be an actual wall opening, not a freestanding object:
- width: 2680 mm;
- height: 1900 mm;
- sill: 500 mm;
- head height: 2400 mm AFF;
- frame and glass centered in the wall thickness;
- wall geometry split around the opening so no solid wall occupies the W3 opening.

## 5. White-model gate

Before styling or furniture:
- build shell, openings, balcony, bathrooms, columns/shafts, and fixed wet utilities;
- support top / plan view;
- render a source-plan overlay in a hideable review layer;
- verify that wall centerlines / faces and openings align with the PDF;
- verify room connectivity and that all plan doors connect the intended spaces.

If overlay alignment fails, stop and correct geometry before style integration.

## 6. Style specification

Translate the supplied reference image into `style.json`.

### Design language
- warm off-white walls, not pure white;
- light natural oak floor;
- low-saturation warm wood cabinetry;
- muted gray-beige upholstery;
- dark gray / black window frames;
- restrained plants and textiles;
- clean modern / Scandinavian-adjacent furniture silhouettes;
- moderate visual density;
- no glossy showroom-white surfaces.

### Lighting / rendering
- ACES tone mapping;
- RoomEnvironment fallback plus HDRI when available;
- soft shadows;
- GTAO / ambient occlusion;
- restrained bloom;
- neutral-warm daylight;
- avoid clipping / overexposure;
- background light gray / off-white, separate from wall material.

### Camera
Default hero view should resemble the user's reference:
- axonometric / orthographic dollhouse;
- lower than a top-down plan;
- full unit tightly framed;
- front cutaway walls reduced or hidden only as a presentation layer; architectural geometry remains fixed.

## 7. Furniture and product evidence

Furniture enters as a replaceable design layer and must not alter architecture.

For v5:
- define roles for sofa, coffee table, lounge chair, dining table/chairs, beds, bedside tables, desks, wardrobes, TV console, kitchen base/tall units, bathroom vanities, sanitary fixtures, and plants;
- where a live market source is found, record exact dimensions and source;
- where no suitable verified product is found, use a `conceptual-proxy` or `procedural-proxy` and label it as such;
- no proxy is allowed to imply a real brand/product identity;
- preserve `productId`, geometry source, fit status, and evidence status through save/share/export.

Target market for research: Taiwan unless a product source explicitly states otherwise.

## 8. Runtime

Use the Skill's `runtime-starter` instead of continuing the current one-file viewer.

Required viewer capabilities for v5:
- orbit;
- axonometric;
- top / plan;
- interior / room focus;
- first-person walkthrough with collision;
- responsive mobile controls;
- one quality control (high / medium / low);
- furniture selection, X/Z move, Y rotate, snap, undo/redo;
- hideable review overlay;
- PNG capture;
- saved state and share hash;
- product/evidence panel;
- architecture remains immutable while design layers are editable.

The default mobile quality tier is `medium`.

The concept-render stage is recorded as **skipped** for v5 unless a new generated concept is needed, because the user has already supplied and approved a visual reference direction.

## 10. Validation

Run, in order:

1. `node scripts/test-scripts.mjs` from the Skill root.
2. `node scripts/image-inventory.mjs <input-dir>`.
3. `node scripts/validate-case.mjs <case-dir> --strict`.
4. `node scripts/check-product-links.mjs <case-dir>`.
5. `npm install` in the copied runtime.
6. `npm run build`.
7. `node scripts/smoke.mjs`.
8. Manual rendered inspection:
   - desktop overall axonometric;
   - top / plan;
   - at least one interior view;
   - mobile viewport;
   - furniture selection / move / rotate / undo;
   - blocked placement;
   - walkthrough collision;
   - state restore / share hash.

A successful build is not accepted as proof of browser behavior.

## 11. Delivery

Publish the verified build to the existing GitHub Pages repository:

`https://legosea.github.io/b2-11f-3d-viewer/`

Delivery must include:
- runnable viewer;
- case JSON files;
- validation receipt;
- assumptions / unknowns;
- representative desktop and mobile screenshots;
- current shareable state URL;
- product evidence export where applicable.

## 12. Acceptance criteria

v5 is accepted only when:

1. top view agrees with the source PDF topology;
2. W3 is embedded in the correct wall and has the confirmed 2680 × 1900 mm opening with 500 mm sill;
3. no invented partitions from v1–v4 remain;
4. the default axonometric view visually reads as the user's warm modern dollhouse reference rather than a white engineering model;
5. no uncaught console errors occur in desktop or mobile smoke tests;
6. mobile rendering is visible and usable;
7. architecture and design layers are independently editable / replaceable;
8. every unresolved dimension or product claim is explicitly marked `estimated`, `inferred`, `unknown`, or `unverified`.
